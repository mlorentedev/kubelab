# Terraform state in R2

> ADR-069, TF-007 (#558). Every root under `infra/terraform/` keeps its state in
> the R2 bucket `kubelab-tfstate` under `<root>/terraform.tfstate`, locked with
> S3-native lockfiles and copied to a locked `history/` prefix on every write.

## The rules

- **Every run goes through the runner**: `toolkit infra terraform run <root> <action>`,
  behind the `tf-*` Make targets. Never run `terraform` by hand. The runner is what
  supplies the backend file, the state credential and the history copy.
- **Never print a state.** It holds secrets in clear (the `r2` root's tokens, for
  one). No action here prints attribute values. `make tf-state-list` prints
  addresses only, and `make tf-state-history` prints keys and dates only.
- **A local `terraform.tfstate` in a module is an error.** The runner refuses every
  action on that root except `migrate` until it is moved.

Prerequisites: the age key on the workstation, Terraform `>= 1.10` and the `aws`
CLI (`dotf tools sync` installs both), and `make worktree-init` in the checkout.

## What lives where

| What | Where |
|---|---|
| Bucket, endpoint, history prefix, retention | `terraform.state` and `backup.r2` in `common.yaml` |
| Backend settings every root inits with | `infra/terraform/backend.s3.tfbackend`, generated by `make sync-terraform-backend` |
| A root's state | `kubelab-tfstate/<root>/terraform.tfstate` |
| Its lock, while a run holds it | `kubelab-tfstate/<root>/terraform.tfstate.tflock` |
| Its history | `kubelab-tfstate/history/<root>/<lineage>/<serial>.tfstate`, under a 365-day bucket lock |
| The state credential | `terraform.state.{access_key_id,secret_access_key}` in `common.enc.yaml` |

## Bootstrap (once per account)

```bash
make tf-state-bootstrap
```

It needs `cloudflare.r2_admin_token` and `cloudflare.r2_token_minter` in SOPS. It
then does three things:

1. It creates the bucket if absent.
2. It sets the lock rule on `history/` if it is absent or differs. Rules with other ids are kept.
3. It mints an Object Read & Write token scoped to `kubelab-tfstate` and checks it by consequence. The token must list the state bucket and be refused on the backups bucket, or it is revoked and nothing is stored. Then the pair is written to `common.enc.yaml`.

Each step logs `created`/`set`/`minted` or `kept`. A second run must log `kept`
three times. Commit the SOPS change in the same PR. Until it lands, every
other checkout fails with `terraform.state.access_key_id is empty or absent`.

## Migrate a root's local state (once per root)

Run it in the checkout that holds the local file:

```bash
make tf-state-migrate ROOT=dns
```

The runner pushes the file without `-force`. Terraform refuses the push if R2
already holds a different lineage or a newer serial. The runner then reads R2
back and accepts the result only if the lineage and the set of resource
addresses match, at the same serial or later. Only then does it rename the local
file to `terraform.pre-remote.tfstate`, which stays gitignored and is never
overwritten. A failed comparison keeps the local file and exits 1. Re-running
after a success is a no-op.

Then, from any other checkout:

```bash
make tf-dns-plan                 # expect: No changes
make tf-state-list ROOT=dns      # the addresses R2 holds
```

Delete the `.pre-remote` copy only after a plan from a second machine reads `No changes`.

## Rotate the state credential

```bash
make tf-state-bootstrap ROTATE=1
```

This mints a new token, checks it the same way, stores it, and then revokes the
old one. Commit the SOPS change. A checkout still holding the old pair fails at
`init` with an access error until it pulls.

## A run is refused because the state is locked

`Error acquiring the state lock` names a lock id, who holds it and since when.
A lock that another run holds right now is the lock working. Wait for that run.

Release the lock only when you know its holder is dead, for example a killed
terminal or a machine that went down mid-apply:

```bash
make tf-state-unlock ROOT=dns LOCK=<lock id from the error>
```

This removes the `.tflock` object only. The state is not read or written. Then
run a plan: a run that died mid-apply can have written part of its changes.

## Restore a state from history

Every action that writes state (apply, destroy, untaint, migrate, restore)
copies the state to history before it starts and again when it ends, whatever
its outcome. If the copy before the write fails, the write does not run.

```bash
make tf-state-history ROOT=dns                          # <lineage>/<serial> and date, per copy
make tf-state-restore ROOT=dns TO=<lineage>/<serial>
make tf-dns-plan                                        # read what the restored state implies
```

A restore writes the old content back as a new state, like a revert. It takes the
serial after the current one, so it needs no `-force`. The state it replaces was
copied to history first, so a restore is undone by restoring that copy. The
runner refuses three cases:

- a copy whose content does not match its key;
- a copy of a different lineage than the one R2 holds, which only `-force` would replace and the runner never passes;
- any restore on a root whose state is still unrecovered.

History cannot be deleted or replaced for 365 days, by anyone, including the
operator. That is the point of it.

## Roots whose state was lost

`gcp`, `gcp-bootstrap` and `vps-firewall` point at empty keys. Their states were
lost before this backend existed, and their recovery is TF-015 (#2226). A plan is
allowed and shows everything the import has to cover. `apply`, `destroy`,
`untaint` and `restore` are refused, because against an empty state Terraform
would create a second copy of what already runs. Until TF-015,
`make gcp-killswitch-prove` cannot run either: it reads the kill switch's service
account from the `gcp-bootstrap` state. `make gcp1-replace` is unaffected, because it
recreates the instance through the managed instance group, not through Terraform.

## Re-measure the lock

```bash
make test-tfstate-lock-live
```

`use_lockfile` relies on R2 letting exactly one of many concurrent conditional
PUTs through, which Cloudflare does not document. This writes under `probe/` with
8 concurrent writers, repeated 10 times, asserts one winner each time, and cleans
up. Run it after any change to R2 or to the backend settings.

## Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| `terraform.state.access_key_id is empty or absent in SOPS` | No bootstrap yet, or the SOPS change is not in this checkout | `make tf-state-bootstrap`, or pull |
| `... is a local state, and the <root> root keeps its state in R2` | A file from before the migration | `make tf-state-migrate ROOT=<root>` |
| `the <root> root's state was lost and is not recovered yet` | An unrecovered root | TF-015 (#2226) |
| `the state could not be copied to history; nothing was changed` | R2 unreachable or the credential refused | Fix access and re-run; nothing was written |
| `InvalidRequest` / signature errors from R2 | A shell `AWS_SESSION_TOKEN` or `AWS_PROFILE` reached the CLI | The runner strips the shell's `AWS_*`; report it as a defect if it still happens |
| `Unsupported Terraform Core version` | Terraform older than 1.10, which has no `use_lockfile` | `dotf tools sync` |
