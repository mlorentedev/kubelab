# console

The operator console's frontend (ADR-074): Astro static output, React islands, Tailwind 4, the same
toolchain as the `web` product. Today it is the forge view, at parity with the page the API
used to embed: the queue, per-source freshness and reachability, a text filter and cursor paging.

The API stays the backend. It serves `GET /console/queue` on the console host, and this app
renders what it answers. It derives nothing (D7). On the console host nginx serves this app at `/` and
Traefik sends `/console/` to the API (D5), so the app reads the absolute path `/console/queue`.

## Develop

```bash
cd apps/console
npm ci
npm run dev        # http://localhost:4321, no cluster and no session
npm test           # view logic, the fixture server and the component, in jsdom
npm run build      # type check (astro check) and static build into dist/
```

Authelia's cookie is scoped to the console host, so a dev server on localhost cannot call a real
`/console/` with a session. `npm run dev` therefore answers `/console/queue` from recorded
responses in `fixtures/` (`dev/fixture-api.ts`). It never proxies to a real host and takes no cookie
from a file or an environment variable.

Pick what the fixtures answer with `CONSOLE_FIXTURE=<scenario> npm run dev`:

| Scenario | Answers |
|---|---|
| `default` (unset) | three pages of 95 open items across five sources, so "N of M" and "Load more" show |
| `degraded` | one page, two sources unreachable, one of them never read |
| `empty` | no sources and no items |
| `unavailable` | the API's 503 |
| `expired` | the redirect Authelia answers an expired session with |

`fixtures/<scenario>/page-N.json` are whole responses in the API's wire shape; page N's `next` is the
cursor that leads to page N+1. They are held to the handler's types by
`TestFixturesMatchTheQueueContract` in `apps/api/src/internal/console`, so a key the API adds or drops
fails the Go suite until the fixtures and `src/lib/contract.ts` follow.

## Layout

| Path | Holds |
|---|---|
| `src/lib/queue.ts` | the view's logic as pure functions: age, item reference, the filter, the paging reducer |
| `src/lib/contract.ts` | the API's answer as types, and the check a decoded answer passes |
| `src/lib/client.ts`, `useQueue.ts` | the read of `/console/queue`, and its refresh loop |
| `src/components/` | `ForgeView` (the island) over `SourceStrip`, `FilterBox` and `ListLayout` of `ItemRow`s |
| `src/styles/brand.css` | the brand tokens as a Tailwind theme, **generated**: `make sync-branding` |
| `dev/`, `fixtures/` | the fixture server for `astro dev`, and what it answers |

The layout is a component over a list of items, so a board that renders the same items in columns
(ADR-074 amendment, #3442) is a sibling of `ListLayout`, not a rewrite of the view.

Colours and fonts come from the brand tokens in `infra/config/values/common.yaml`. Write no hex value
here: `brand.css` is regenerated by `make sync-branding`, which `make sync-branding-check` verifies.
