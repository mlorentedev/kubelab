# BACKUP-044 — tasks

> Drafted after Part 0, not before. Every number below was measured against the
> live fleet rather than assumed; the transcripts are in `verification.md`. Do not
> re-derive them — and do not soften them either, because two of them corrected
> the proposal.

## Part 0 — settle the risks (DONE 2026-08-16)

- [x] **R2 — the destination exists and works.** Bucket `kubelab-backups`, Account API token (not a User token — a user token goes inactive if its user leaves the account, which for a backup credential is a silent-failure vector). Credentials in SOPS, non-secrets as SSOT at `infra.backup_r2`. Proved by `make backup-verify-destination` *and* `make backup-verify-restic`: scope refused ListBuckets, write/read/sha256/delete round-trip, then restic init/backup/snapshots/check. ✓ 2026-08-16
- [x] **R1 — the repository password is escrowed outside SOPS.** Generated by `make backup-generate-password`, copied to a Bitwarden item alongside the R2 credentials. SOPS is decrypted by an age key a disaster destroys; without the second copy the backups are intact and unopenable. Not in the `dotf secrets` registry — that is age-backed today, which would return to the same trust root. ✓ 2026-08-16
- [x] **R3 — restic fits the RPi3.** ~60 MB steady-state peak RSS against 428 MB available; `check` moved 58.0 → 58.8 MB between a fresh repository and one with 42 snapshots, so memory does not climb with repository size at this scale. First backup of 18 MB peaks at 158 MB and still fits. ✓ 2026-08-16
- [x] **R4 — boot ordering differs per node.** The Beelink has `kubelab-compose.service` to order against; the RPi4 has no systemd unit at all, so only `docker.service` is orderable there. `Persistent=true` is the wrong instrument either way — it governs when a missed timer catches up, not what it runs before. ✓ 2026-08-16
- [x] **R5 — the live Uptime Kuma volume is `uptime_kuma_data`.** The orphan `uptime-kuma_uptime_kuma_data` is *larger* (26M vs 19M) and frozen since 2026-03-28. Size, name plausibility and completeness all point at the wrong one. ✓ 2026-08-16
- [x] **R6 — restores go into an ephemeral instance**, never over live data. ✓ 2026-08-16
- [x] **AC7 costing.** `backup` 110 Class A ops, `check` 80, `snapshots` 60. Per-run `check` would be 31% of the free tier, not the near-exhaustion feared. ✓ 2026-08-16

## Approved operating parameters

Decided by the operator 2026-08-16 on the measured arithmetic. Bake these in; do
not re-open them during implementation.

| Parameter | Value | Why |
|---|---|---|
| Always-on schedule | every **4h** (wall-clock) | #452 ratifies Tier 1 at RPO < 6h; hourly over-delivered and cost 119k operations a month to do it |
| On-demand schedule | hourly **while up**, plus boot and graceful shutdown | a 6h threshold never fires in a 3-4h session (#1090) |
| `restic check` | **weekly**, not per-run | the remaining operations lever; leaves 16x headroom for repository growth |
| Retention | `--keep-daily 7 --keep-weekly 4 --keep-monthly 6` | ~a year of restore points; dedup makes the history nearly free (42 snapshots cost 2.6 MB in the rig) |
| Storage class | **Standard** | the free tier does not apply to Infrequent Access — the cheaper-looking class is the more expensive one here |

Projected: ~63,000 Class A operations a month against 1,000,000 free, and ~32 MB
of source against 10 GB.

## Part 1 — the Ansible role

- [ ] **Install prerequisites.** Neither `sqlite3` nor `restic` is present on any of the four nodes (measured; all `aarch64`, Debian 13 on the RPi3). The role owns both installs. The RPi3 has the least headroom, so verify its install does not disturb Uptime Kuma.
- [ ] [AC6] **Sources as an SSOT allow-list in `common.yaml`**, never an exclude list. The current `backup` role enumerates every Docker volume minus exclusions, which is why the VPS backs up ~306M of dead pre-K3s volumes while six nodes are uncovered (#1092). Name `uptime_kuma_data` and `coredns_pihole_data` explicitly — the orphan and `gravity.db` must be omitted *by not being listed*, not by being excluded.
- [ ] [AC2] **`sqlite3 .backup` before archiving**, for all four live SQLite databases. Pi-hole's FTL carried a 3 MB `-wal` at measurement; a file copy loses it silently.
- [ ] **Exclude `gravity.db`** (4.5 MB, Tier 3 — `pihole -g` regenerates it in full). Its neighbour `pihole-FTL.db` is in scope; the names are similar and the tiers differ.
- [ ] **One restic repository per node**, addressed from `infra.backup_r2.repo_prefix` + the node name. A compromised node must not be able to rewrite another's history.
- [ ] Credentials reach restic **through the environment**, never as arguments — `RESTIC_PASSWORD` and the two `AWS_*` values, so nothing lands in the process list.

## Part 2 — triggers

- [ ] **Always-on nodes (VPS, RPi3):** systemd timer every 4h.
- [ ] [AC5] **On-demand nodes (Beelink, RPi4):** boot + hourly while up + graceful shutdown. The Beelink orders with `Before=kubelab-compose.service`; the RPi4 has no such unit, so it orders against `docker.service` — which means its snapshot runs before Docker starts and the database is quiescent. Two designs, deliberately.
- [ ] Do **not** generalise the on-demand asymmetry fleet-wide. It exists because a threshold at or above session length never fires.

## Part 3 — verification and observability

- [ ] [AC7] Weekly `restic check` as its own timer, separate from the backup run.
- [ ] Retention: `forget` with the policy above, plus `prune`. The R2 token's delete permission is what makes this work and was proved in Part 0.
- [ ] [AC4] **A failed run alerts** on the #686 path. A window missed because an on-demand node was off must **not** alert — demonstrated across a real power cycle, not by reading config.
- [ ] [AC9] **A run that never happened is reported.** One place answers "when did each node last succeed", and a node past its window alerts unprompted. This is the coverage view — the failure that survives every check asserting recent snapshots look healthy. Demonstrate by stopping a timer.

## Part 4 — prove it

- [ ] [AC1] Every node-path consumer present in its R2 repository, verified by listing snapshots **from a machine that is not the source node**.
- [ ] [AC3] **A restore exercised end to end** for Gitea and one always-on consumer, into a scratch location per R6, with `PRAGMA integrity_check` on the restored database and the transcript in `verification.md`. Content verified, not exit codes.

## Explicitly not here

The PVC class is **BACKUP-046 (#1111)** — Authelia, Postgres, Grafana, n8n,
CrowdSec db. Three of those five have no backup at all today, and Postgres has no
mechanism in any spec (it needs `pg_dump`, not `sqlite3 .backup`). Do not let it
creep in: the split is by mechanism, and the tier axis cannot make it because
Authelia and Postgres are Tier 1 *and* PVCs.
